Why tables?

As soon as an editor shows many objects with several fields each, you want a spreadsheet: aligned columns, sortable headers, resizable widths, maybe hidden columns. Think entity lists, asset databases, profiler captures, input bindings. Dear ImGui's Tables API does all of that, and it is also the best general-purpose layout tool (lesson 7 used it for the property grid).

The basic shape

if (ImGui::BeginTable("##entities", 3, ImGuiTableFlags_Borders | ImGuiTableFlags_RowBg))
{
    ImGui::TableSetupColumn("Name");        // optional: column names + flags
    ImGui::TableSetupColumn("Mesh");
    ImGui::TableSetupColumn("Visible");
    ImGui::TableHeadersRow();               // optional: draw the header row

    for (int i = 0; i < gEntityCount; i++)
    {
        ImGui::TableNextRow();
        ImGui::TableNextColumn(); ImGui::TextUnformatted(gEntities[i].name);
        ImGui::TableNextColumn(); ImGui::TextUnformatted(gMeshNames[gEntities[i].mesh]);
        ImGui::TableNextColumn(); ImGui::Text("%s", gEntities[i].visible ? "yes" : "no");
    }
    ImGui::EndTable();                      // only if BeginTable returned true
}

TableNextColumn() moves to the next cell, wrapping to a new row when needed. TableSetColumnIndex(n) jumps to a specific column. You must call one of them before submitting content: after TableNextRow() alone, nothing will show.

Table flags

ImGuiTableFlags_Effect
BordersInner and outer borders (or pick BordersInnerV, BordersOuter...)
RowBgAlternating row colours. Makes wide tables much easier to read
ResizableDrag column borders to resize
ReorderableDrag headers to reorder columns (needs TableHeadersRow)
HideableRight-click a header to hide/show columns
SortableClick headers to sort. You do the sorting (see below). Add SortMulti for shift+click
ScrollYThe table becomes its own scrolling region. Needs an outer size in BeginTable
SizingStretchPropColumns stretch to fill the width, with weights proportional to their content

The lesson code puts checkboxes for these flags above the table (CheckboxFlags toggles one bit in an int), so you can flip them live and see the effect.

Columns

// label, flags, width (px for fixed, weight for stretch), user ID
ImGui::TableSetupColumn("#",        ImGuiTableColumnFlags_WidthFixed | ImGuiTableColumnFlags_NoHide, 30.0f, COL_INDEX);
ImGui::TableSetupColumn("Name",     ImGuiTableColumnFlags_WidthStretch | ImGuiTableColumnFlags_DefaultSort, 1.2f, COL_NAME);
ImGui::TableSetupColumn("Position", ImGuiTableColumnFlags_WidthStretch, 2.0f, COL_POSITION);
ImGui::TableSetupColumn("Color",    ImGuiTableColumnFlags_WidthFixed | ImGuiTableColumnFlags_NoSort, 45.0f, COL_COLOR);
ImGui::TableSetupScrollFreeze(0, 1);   // freeze 0 columns, 1 row (the header) while scrolling
ImGui::TableHeadersRow();

Useful column flags: WidthFixed, WidthStretch, DefaultSort, NoSort, NoHide, NoResize, PreferSortDescending, DefaultHide.

Sorting: sort an index array, not your entities

ImGui never sorts your data. It gives you sort specs (which column, ascending or descending) and a SpecsDirty flag that says "the user clicked a header, sort again".

Don't reorder gEntities[]

Sorting the actual entity array would change every entity's index. gSelectedEntity would then point at a different object, as would any other index stored elsewhere (in an editor, a script, the undo stack...). The table is a view. Keep a separate array of indices and sort that.

static int order[MAX_ENTITIES], orderCount = -1;
static const ImGuiTableSortSpecs *sortSpecs;   // qsort has no user-data pointer

static int CompareEntities(const void *pa, const void *pb)
{
    int ia = *(const int *)pa, ib = *(const int *)pb;
    for (int n = 0; n < sortSpecs->SpecsCount; n++)
    {
        const ImGuiTableColumnSortSpecs *s = &sortSpecs->Specs[n];
        int d = 0;
        switch (s->ColumnUserID)
        {
        case COL_NAME: d = _stricmp(gEntities[ia].name, gEntities[ib].name); break;
        case COL_MESH: d = gEntities[ia].mesh - gEntities[ib].mesh; break;
        }
        if (d) return (s->SortDirection == ImGuiSortDirection_Ascending) ? d : -d;
    }
    return ia - ib;   // tie-break keeps the order stable
}

// after TableHeadersRow():
ImGuiTableSortSpecs *specs = ImGui::TableGetSortSpecs();
if ((specs && specs->SpecsDirty) || orderCount != gEntityCount)
{
    for (int i = 0; i < gEntityCount; i++) order[i] = i;
    orderCount = gEntityCount;
    sortSpecs = specs;
    qsort(order, gEntityCount, sizeof(int), CompareEntities);
    specs->SpecsDirty = false;
}
// rows: for (row...) { int i = order[row]; Entity *e = &gEntities[i]; ... }

Use the column's user ID (the 4th argument of TableSetupColumn) in the switch rather than ColumnIndex. That way sorting stays correct after the user reorders columns. We also re-sort when the entity count changes, since the old index list would be out of date.

Why not sort every frame?

For 128 entities it would be cheap, but it would feel wrong. If you sort by position and drag an entity's X value, the row would jump around under your mouse while you edit it. Sorting only when the specs change (or the list changes size) keeps rows still while you work.

Selectable rows

To make a whole row clickable, put a Selectable in the first column with ImGuiSelectableFlags_SpanAllColumns. Add AllowOverlap so the widgets in the other cells (checkbox, colour swatch) can still be clicked on top of it:

ImGui::TableNextRow(ImGuiTableRowFlags_None, rowHeight);
ImGui::TableSetColumnIndex(0);
if (ImGui::Selectable(label, gSelectedEntity == i,
                      ImGuiSelectableFlags_SpanAllColumns | ImGuiSelectableFlags_AllowOverlap,
                      ImVec2(0, rowHeight)))
    gSelectedEntity = i;

Editable cells

Each cell can hold any widget. Two rules make it work:

  1. PushID per row. Every row has a "##name" input, a "##vis" checkbox and so on. Without PushID(i), all rows share the same IDs and editing one edits... whichever ImGui finds first.
  2. SetNextItemWidth(-FLT_MIN) before each widget, so it fills the cell instead of using the default width and leaving room for a label.
ImGui::PushID(i);
ImGui::TableNextColumn();
ImGui::SetNextItemWidth(-FLT_MIN);
ImGui::InputText("##name", e->name, sizeof(e->name));
if (ImGui::IsItemActivated()) gSelectedEntity = i;     // clicking into a cell selects the row

ImGui::TableNextColumn();
ImGui::Checkbox("##vis", &e->visible);

ImGui::TableNextColumn();
ImGui::ColorEdit4("##col", e->color, ImGuiColorEditFlags_NoInputs | ImGuiColorEditFlags_NoLabel);
ImGui::PopID();
Game-engine angle

Tables are great for bulk editing: hide the 40 lights in a level with a few checkbox clicks, sort by name to find duplicates, sort by position to find objects that fell below the floor. The "sort a view, not the data" rule comes back everywhere: the asset browser, the profiler, the log. For thousands of rows, combine the table with ImGuiListClipper (lesson 8). It works inside ScrollY tables as is, iterating over order[].
