This is the most important "gotcha" in Dear ImGui, and every engine UI runs into it on the first entity list. Learn it now and you'll save yourself hours of confusing bugs.

Why widgets need IDs

ImGui keeps no widget objects, but it still has to remember a few things between frames: which slider is being dragged, which tree node is open, which text field has the cursor. It identifies each widget by an ID, a 32-bit hash computed from:

ID = hash( ID stack  +  widget label )
            ^ window name, tree nodes, PushID() values...

By default the label you pass is both the visible text and the ID source. Two widgets with the same label in the same window therefore get the same ID.

The broken entity list

Here's what everyone writes first:

// BROKEN - every row has the same IDs
ImGui::Begin("Scene List");
for (int i = 0; i < gEntityCount; i++)
{
    Entity *e = &gEntities[i];
    ImGui::Checkbox("Visible", &e->visible);   // ID = hash("Scene List" + "Visible")  - same every row!
    ImGui::SameLine();
    ImGui::Text("%s", e->name);
    ImGui::SameLine();
    if (ImGui::Button("Select"))               // ID = hash("Scene List" + "Select")   - same every row!
        gSelectedEntity = i;
}
ImGui::End();

What happens when you run it:

  • Clicking Select on row 4 activates the ID, but every row reacts to that same ID. Depending on the widget, the first row "steals" the click, or several rows respond.
  • Checkboxes toggle the wrong entity, or appear to ignore clicks.
  • This ImGui version shows a red "Programmer error: N visible items with conflicting ID!" tooltip when you hover a colliding widget. That's io.ConfigDebugHighlightIdConflicts, which is on by default. Pay attention to it.

Fix 1: PushID / PopID in loops

PushID adds a value to the ID stack. Every widget submitted until the matching PopID includes that value in its hash:

// FIXED
for (int i = 0; i < gEntityCount; i++)
{
    Entity *e = &gEntities[i];
    ImGui::PushID(i);                          // stack: "Scene List" / i
    ImGui::Checkbox("##vis", &e->visible);     // ID = hash("Scene List" / i / "##vis")  - unique
    ImGui::SameLine();
    ImGui::Text("%s", e->name);
    ImGui::SameLine();
    if (ImGui::SmallButton("Select"))          // ID = hash("Scene List" / i / "Select") - unique
        gSelectedEntity = i;
    ImGui::PopID();                            // must ALWAYS match PushID
}
OverloadUse when
PushID(int)Loop index or a numeric entity ID. The simplest choice.
PushID(const void*)A pointer to the object, e.g. PushID(e). Stable as long as the object doesn't move in memory.
PushID(const char*)A unique string such as a file path or GUID text.
Index vs stable ID

An index ID belongs to a row position, not to an object. When you delete entity 2, entity 3 becomes index 2 and inherits row 2's ImGui state (open tree node, active text field). The engine's gEntities[] array is compacted on removal, so pointers move too. A real engine gives each entity a permanent unique ID (a uint32 or GUID) and calls PushID((int)entity.uid). ImGui Lab's Entity struct has no such field, so we use the index, which is fine for this list.

Fix 2: "##" hides part of the label

Everything after ## is used for the ID but not displayed:

ImGui::Checkbox("##vis", &e->visible);        // no visible label at all
ImGui::Button("Delete##entity");               // shows "Delete"
ImGui::Button("Delete##component");            // also shows "Delete", but a different ID
ImGui::SliderFloat("##speed", &speed, 0, 10);  // label-less slider (common in tables)
Empty labels collide too

ImGui::Button("") twice in one window is a collision. Always give label-less widgets a ##name.

Fix 3: "###" keeps the ID while the label changes

With ## the whole string is still hashed, so changing the visible part changes the ID. With ### only the part after ### is hashed:

char label[64];
snprintf(label, sizeof(label), "Clicked %d times###clickCounter", clicks);
ImGui::Button(label);                          // ID = hash("clickCounter"), whatever the text says

// Works for windows too: the title changes, the window (position, size) stays the same
snprintf(title, sizeof(title), "Inspector - %s###Inspector", e->name);
ImGui::Begin(title);

Without ###, a window titled "Inspector - Crate" would become a new window the moment you selected the Planet, and it would jump back to its default position.

GetID and the ID stack

ImGuiID a = ImGui::GetID("Select");    // what ID would "Select" get right here?
ImGui::PushID(0);
ImGuiID b = ImGui::GetID("Select");    // different: the stack now contains 0
ImGui::PopID();

These things push onto the ID stack for you: Begin() (the window name), TreeNode() (while open), BeginChild(), BeginTable(), BeginMenu(), BeginTabItem(). That's why two different windows can both have a "Select" button without any problem.

Debugging IDs

  • ID Stack Tool: ImGui::ShowIDStackToolWindow(&open), or Demo > Tools. Hover any widget to see the full path of the ID: window, PushID values, label, and the resulting hash. Hover two "Select" buttons in the example and compare.
  • Conflict tooltip: the red tooltip described above appears automatically on colliding items.
  • Metrics/Debugger: ShowMetricsWindow() > Tools > Item Picker. Click a widget and ImGui triggers a debugger breakpoint inside the code that submitted it, with the call stack pointing to your line.
Item Picker needs a debugger

The Item Picker calls __debugbreak(). If no debugger is attached, Windows treats that as a crash and the program closes. Use it only when you've started the exe from Visual Studio (Debug > Attach to Process works too).

Game-engine angle

Editor UIs are full of repeated widgets: one row per entity in the hierarchy, one "Remove" button per component in the inspector, one slider per material parameter, one thumbnail per asset. The rule is simple: whenever you submit widgets in a loop, wrap the body in PushID/PopID, ideally with the object's permanent ID. For example:

for (each component c in entity)
{
    ImGui::PushID(c);                       // pointer or component id
    if (ImGui::CollapsingHeader(c->TypeName()))
        c->DrawInspector();                 // its own widgets can reuse labels freely
    ImGui::PopID();
}
