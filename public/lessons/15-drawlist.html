Underneath every widget: ImDrawList

Every button, slider and window you have drawn so far ends up as triangles in an ImDrawList. A draw list is a growing buffer of vertices, indices and draw commands that the OpenGL2 backend renders at the end of the frame. You can append your own shapes to it, and that is how you build custom widgets, node editors, timelines and in-viewport overlays.

Three lists to choose from

ImGui::GetWindowDrawList()with the current window, clipped to it, scrolls with itcustom widgets, canvases, mini-maps

Order of things on screen

In the mini engine: RenderScene() (OpenGL) first, then ImGui renders the background list, then every window, then the foreground list. The engine's own "RMB orbit | MMB pan..." hint uses the background list too.

Screen coordinates

Draw list functions take absolute screen pixels (0,0 = top-left of the client area), not window-relative positions. To draw inside a window, ask where the layout cursor is:

ImVec2 p0   = ImGui::GetCursorScreenPos();               // where the next widget would go
ImVec2 size = ImVec2(ImGui::GetContentRegionAvail().x, 200);
ImGui::InvisibleButton("##canvas", size);               // claim the space + get mouse interaction
ImVec2 p1   = ImVec2(p0.x + size.x, p0.y + size.y);

ImDrawList *dl = ImGui::GetWindowDrawList();
dl->AddRectFilled(p0, p1, IM_COL32(25, 28, 36, 255), 4.0f);   // background, rounded 4 px

The InvisibleButton is important. It advances the layout so the next widget goes below your canvas, and it gives you IsItemHovered() / IsItemActive() for free.

No ImVec2 operators here

ImGui only defines + - * / for ImVec2 if you #define IMGUI_DEFINE_MATH_OPERATORS before including imgui.h. OGL.c doesn't, so the lesson uses tiny helpers like L15_Add(a, b). In your own engine, defining it is fine.

Building a custom widget: the knob

A custom widget follows the same recipe every time: claim space with InvisibleButton, handle input through item queries, draw with the window draw list, and return "changed" like the built-in widgets do.

static bool L15_Knob(const char *label, float *v, float vmin, float vmax, float radius)
{
    ImVec2 pos = ImGui::GetCursorScreenPos();
    ImVec2 center(pos.x + radius, pos.y + radius);
    ImGui::InvisibleButton(label, ImVec2(radius * 2, radius * 2));       // 1. space + ID
    bool changed = false;
    if (ImGui::IsItemActive() && ImGui::GetIO().MouseDelta.x != 0.0f)    // 2. input
    {
        *v += ImGui::GetIO().MouseDelta.x * (vmax - vmin) / 200.0f;      //    200 px = full range
        *v = *v < vmin ? vmin : (*v > vmax ? vmax : *v);
        changed = true;
    }
    float t = (*v - vmin) / (vmax - vmin);
    float a = 3.14159f * (0.75f + 1.5f * t);                             // 270 degree sweep
    ImDrawList *dl = ImGui::GetWindowDrawList();                          // 3. draw
    dl->AddCircleFilled(center, radius, ImGui::GetColorU32(ImGuiCol_FrameBg));
    dl->AddLine(center, ImVec2(center.x + cosf(a) * radius, center.y + sinf(a) * radius), IM_COL32_WHITE, 2.0f);
    return changed;                                                       // 4. same contract as SliderFloat
}

L15_Knob("Yaw", &gCamera.yaw, -180.0f, 180.0f, 30.0f);   // drives the engine camera directly

The lesson's joystick works the same way. While the item is active, the offset of the mouse from the centre (clamped to a ring) becomes a yaw/pitch rate, and the stick snaps back to the centre when you release it.

Drawing over the 3D world

Engine_WorldToScreen(world, &screen) wraps gluProject with the camera matrices from this frame and flips Y to ImGui's top-down convention. It returns false for points behind the camera. With it, any 3D position can carry 2D UI:

ImDrawList *bg = ImGui::GetBackgroundDrawList();     // over the scene, under the windows
for (int i = 0; i < gEntityCount; i++)
{
    float top[3] = { gEntities[i].position[0], gEntities[i].position[1] + gEntities[i].scale[1] * 0.5f, gEntities[i].position[2] };
    ImVec2 s;
    if (!Engine_WorldToScreen(top, &s)) continue;    // behind the camera
    ImVec2 ts = ImGui::CalcTextSize(gEntities[i].name);
    bg->AddText(ImVec2(s.x - ts.x * 0.5f, s.y - ts.y - 4), IM_COL32_WHITE, gEntities[i].name);
}

For screen-space brackets, the lesson projects the 8 corners of each entity's box, takes the 2D min/max, and draws short L-shaped lines at each corner. That is the classic "target lock" look, and it scales naturally with distance.

Orientation gizmo

To show which way the world axes point, build the camera's right and up vectors (the same ones gluLookAt builds internally). Then project each world axis onto them. For axis X = (1,0,0), dot(X, right) is simply right[0]:

ImVec2 tip(c.x + right[i] * len, c.y - up[i] * len);   // minus: screen Y points down
bg->AddLine(c, tip, axisColour[i], 3.0f);

Drawing the axes from farthest to nearest (sorted by dot(axis, forward)) makes the overlap look right.

A clickable mini-map

A top-down map is a canvas whose coordinates are a scaled copy of the world's X/Z plane. Converting in both directions is one multiply and one add:

float k = side * 0.5f / worldHalf;                                  // pixels per metre
ImVec2 ep(mid.x + e->position[0] * k, mid.y + e->position[2] * k);  // world -> map
if (ImGui::IsItemActive())                                          // map -> world
{
    gCamera.target[0] = (io.MousePos.x - mid.x) / k;
    gCamera.target[2] = (io.MousePos.y - mid.y) / k;
}
Draw lists are cheap

Hundreds of labels and lines per frame cost very little. ImGui batches them into a handful of draw calls. The expensive part is usually CalcTextSize on long strings, and even that is fast.

Game-engine angle

World-space overlays are a big part of what makes an editor feel like an editor: light and camera icons, name tags, collision bounds, nav-mesh debug lines, sound radii, "you are here" markers. Many engines run a whole debug-draw system through GetBackgroundDrawList() (2D) next to a 3D line renderer. Custom widgets like the knob show up in curve editors, colour gradients, timelines and audio mixers. When you need a full 3D translate/rotate gizmo, ImGuizmo (lesson 19) is built exactly this way, on top of ImDrawList.

// 3) toggle switch
static bool L15_ToggleSwitch(const char *id, bool *v)
{
    float h = ImGui::GetFrameHeight(), w = h * 1.8f;
    ImVec2 p = ImGui::GetCursorScreenPos();
    bool clicked = ImGui::InvisibleButton(id, ImVec2(w, h));
    if (clicked) *v = !*v;
    ImDrawList *dl = ImGui::GetWindowDrawList();
    dl->AddRectFilled(p, ImVec2(p.x + w, p.y + h), *v ? IM_COL32(66, 150, 250, 255) : IM_COL32(80, 80, 90, 255), h * 0.5f);
    float cx = *v ? p.x + w - h * 0.5f : p.x + h * 0.5f;
    dl->AddCircleFilled(ImVec2(cx, p.y + h * 0.5f), h * 0.5f - 2.0f, IM_COL32_WHITE);
    return clicked;
}
