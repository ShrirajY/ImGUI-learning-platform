Menus: the editor's command centre

A main menu bar is where every editor command lives, so users can discover them. Keyboard shortcuts are the fast path to the same commands. In ImGui a menu is just a popup window full of MenuItems:

if (ImGui::BeginMainMenuBar())                 // full-width bar at the top of the screen
{
    if (ImGui::BeginMenu("File"))              // true while the menu is open
    {
        if (ImGui::MenuItem("New Scene", "Ctrl+N")) RequestNewScene();
        if (ImGui::MenuItem("Quit", "Ctrl+Q"))      Engine_Quit();
        ImGui::EndMenu();                      // only if BeginMenu returned true
    }
    ImGui::EndMainMenuBar();                   // only if BeginMainMenuBar returned true
}

Panel toggles are the classic use of the bool* form. The same bool is passed to Begin("Scene", &showScene), so the window's [x] button and the View menu both control it:

// View menu
ImGui::MenuItem("Scene", NULL, &showScene);
// later
if (showScene) { ImGui::Begin("Scene", &showScene); /* ... */ ImGui::End(); }

if (ImGui::BeginMenuBar())                                    // 2. fill it

Real keyboard shortcuts

The "Ctrl+D" text in a menu does nothing by itself. To make it work, test the key chord every frame, outside the menu (a closed menu's code doesn't run). Dear ImGui 1.90+ has a routing-aware function for this:

const ImGuiInputFlags g = ImGuiInputFlags_RouteGlobal;
if (ImGui::Shortcut(ImGuiMod_Ctrl | ImGuiKey_D, g)) CmdDuplicate();
if (ImGui::Shortcut(ImGuiKey_Delete, g))            CmdRequestDelete();
FunctionNotes
Shortcut(chord, flags)Registers a route. Only one owner gets the key, and focused windows or active widgets win over global routes. The default route is RouteFocused: it only fires while the current window has focus
IsKeyChordPressed(chord)Raw check: were these mods and this key pressed? No routing, no focus checks
IsKeyPressed(ImGuiKey_X)Single key, with optional repeat
Why RouteGlobal?

After you click in the 3D view, no ImGui window has focus. A plain Shortcut(Ctrl+D) called from Lesson_UI (outside any window) would then never fire. RouteGlobal fires regardless, but focused windows that register the same chord still take priority.

Don't steal keys from text fields

Single-key shortcuts like Delete, F or P must not fire while the user is typing an entity name. Skip all shortcuts while ImGui::GetIO().WantTextInput is true. Also skip them while a menu or modal is open: ImGui::IsPopupOpen("", ImGuiPopupFlags_AnyPopup).

In the lesson, every command is a small function (L10_CmdDuplicate, L10_CmdRequestDelete...) that the menu, the buttons and the shortcut all call. One action, three entry points, one implementation.

Popups: OpenPopup + BeginPopup

A popup is a window that floats on top and closes when you click outside it. You open it once, as an event, and begin it every frame:

if (ImGui::Button("Presets..."))
    ImGui::OpenPopup("ColorPresets");          // call ONCE, on the click

if (ImGui::BeginPopup("ColorPresets"))         // call EVERY frame; true while open
{
    if (ImGui::ColorButton("##red", ImVec4(1, 0, 0, 1)))
    {
        SetColor(red);
        ImGui::CloseCurrentPopup();            // Selectable/MenuItem close automatically, buttons don't
    }
    ImGui::EndPopup();
}

Modals: confirm dialogs

BeginPopupModal is a popup that dims the screen and blocks everything else until it is closed. It is the right tool for "are you sure?" questions:

ImGui::SetNextWindowPos(ImGui::GetMainViewport()->GetCenter(), ImGuiCond_Appearing, ImVec2(0.5f, 0.5f));
if (ImGui::BeginPopupModal("Delete entity?", NULL, ImGuiWindowFlags_AlwaysAutoResize))
{
    ImGui::Text("Delete '%s'?\nThis cannot be undone.", gEntities[gSelectedEntity].name);
    if (ImGui::Button("Delete", ImVec2(120, 0))) { CmdDeleteNow(); ImGui::CloseCurrentPopup(); }
    ImGui::SameLine();
    if (ImGui::Button("Cancel", ImVec2(120, 0))) ImGui::CloseCurrentPopup();
    ImGui::SetItemDefaultFocus();              // keyboard focus on Cancel = the safe default
    ImGui::EndPopup();
}

Pass a bool* as the second argument to get a close [x] in the title bar, as in the About box. Modals don't close on Escape by default, so the lesson checks IsKeyPressed(ImGuiKey_Escape) inside each modal.

The OpenPopup ID gotcha

This catches everyone once. A popup's name is hashed with the current ID stack, exactly like a widget label. OpenPopup("X") and BeginPopup("X") only refer to the same popup if they are called with the same ID stack.

// BROKEN: OpenPopup runs inside the "Help" menu window (different ID stack)
if (ImGui::BeginMenu("Help"))
{
    if (ImGui::MenuItem("About")) ImGui::OpenPopup("About");   // ID hashed inside the menu's own window
    ImGui::EndMenu();
}
// ... top level
if (ImGui::BeginPopupModal("About")) { ... }                   // different ID stack -> never opens
// FIXED: the menu only sets a request flag; open + begin happen side by side
if (ImGui::MenuItem("About")) reqAbout = true;
// ... top level
if (reqAbout) { ImGui::OpenPopup("About"); reqAbout = false; }
if (ImGui::BeginPopupModal("About")) { ... }

The same thing happens with PushID(i) loops: an OpenPopup inside a row loop and a BeginPopup after the loop won't match. The request-flag pattern also lets shortcuts open the same modal, since the Delete key handler has no window at all.

Tooltips

ImGui::Button("Duplicate");
ImGui::SetItemTooltip("Ctrl+D");               // text tooltip for the previous item

ImGui::Selectable(e->name, selected);
if (ImGui::BeginItemTooltip())                 // rich tooltip: any widgets
{
    ImGui::ColorButton("##c", ImVec4(e->color[0], e->color[1], e->color[2], 1), 0, ImVec2(40, 40));
    ImGui::SameLine();
    ImGui::Text("Mesh: %s\nPos: %.1f %.1f %.1f", gMeshNames[e->mesh], e->position[0], e->position[1], e->position[2]);
    ImGui::EndTooltip();                       // only if BeginItemTooltip returned true
}

SetItemTooltip and BeginItemTooltip use a short hover delay and require the mouse to be stationary (ImGuiHoveredFlags_ForTooltip), so tooltips don't flicker as you sweep across a list. BeginTooltip() with no condition shows one immediately. Use it for things like a drag-and-drop preview.

Game-engine angle

The "unsaved changes" flag (L10_dirty) is set by every command and every widget that returns true. That one bool drives the menu bar status, the Reset confirmation and, later, the window title asterisk and the "quit without saving?" prompt. Notice that the modal only appears when there is something to lose. Asking every time trains users to click "Yes" without reading.

Camera keys

The engine moves the camera with WASD when ImGui doesn't want the keyboard. Holding Ctrl+D therefore also nudges the camera right. A real editor would skip camera movement while Ctrl is held, or only move the camera while the right mouse button is down.

  2. Show an asterisk in the Scene window's title when the scene is dirty, without losing the window's position. Hint: "Scene *###Scene". Everything after ### is the ID.
  3. Add a Quit confirmation modal that only appears when L10_dirty is true, used by both File > Quit and Ctrl+Q.

if (ImGui::Shortcut(ImGuiMod_Ctrl | ImGuiKey_RightArrow, g) && gEntityCount > 0)

static bool L10_reqQuitModal = false;

// File menu + shortcut call L10_CmdRequestQuit() instead of Engine_Quit()

if (L10_reqQuitModal) { ImGui::OpenPopup("Quit?"); L10_reqQuitModal = false; }
