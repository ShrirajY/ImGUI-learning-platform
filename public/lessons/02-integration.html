This lesson goes through the starter OGL.c from setup\ImGui_OpenGL_Template: a normal Win32 + fixed-function OpenGL program (window, WndProc, initialize, display, update, uninitialize) with Dear ImGui added. Every ImGui addition is wrapped in a banner, so you can find them all by searching for IMGUI.

//================================IMGUI==============================================
    ... ImGui code ...
//===================================================================================

There are only six such banners. Five are small hooks inside the functions you already know, and the sixth holds three helper functions at the bottom of the file:

#WhereWhat it adds
1Top of fileImGui headers, the WndProc handler declaration, the three IMGUI_* prototypes, UI variables
2WndProc()Give every message to ImGui first
3initialize()Call IMGUI_initialize() after the GL context exists
4display()Use a UI-controlled clear color, then call IMGUI_display() before SwapBuffers()
5uninitialize()Call IMGUI_uninitialize() before the GL context is deleted
6Bottom of fileThe bodies of IMGUI_initialize(), IMGUI_display(), IMGUI_uninitialize()

1. Headers and declarations

//================================IMGUI==============================================
// ImGui is a C++ library, so run.bat compiles this file as C++ using /TP
#include "imgui.h"
#include "imgui_impl_win32.h"
#include "imgui_impl_opengl2.h"

extern IMGUI_IMPL_API LRESULT ImGui_ImplWin32_WndProcHandler(HWND hWnd, UINT msg, WPARAM wParam, LPARAM lParam);

void IMGUI_initialize(void);
void IMGUI_display(void);
void IMGUI_uninitialize(void);

static bool g_ImGuiInitialized = false;

// values controlled from the ImGui window
float gClearColor[3] = { 0.1f, 0.1f, 0.1f };
bool  gRotate = true;
//===================================================================================
  • imgui.h is the whole public API: ImGui::Begin, Button, SliderFloat, and so on.
  • imgui_impl_win32.h and imgui_impl_opengl2.h declare the two backends (lesson 01): Win32 for input, OpenGL2 for drawing.
  • The extern line is needed because imgui_impl_win32.h hides the WndProc handler declaration behind #if 0, so that the header doesn't force <windows.h> on everyone. You declare it yourself after including windows.h.
  • gClearColor and gRotate are ordinary globals. The ImGui window edits them, and the existing OpenGL code reads them.

2. Forward input in WndProc

LRESULT CALLBACK WndProc(HWND hwnd, UINT iMsg, WPARAM wParam, LPARAM lParam)
{
//================================IMGUI==============================================
    // Give every window message to ImGui first (mouse, keyboard, ...)
    if (ImGui_ImplWin32_WndProcHandler(hwnd, iMsg, wParam, lParam))
        return TRUE;
//===================================================================================

    switch (iMsg)
    {
    ...

The Win32 backend reads WM_MOUSEMOVE, WM_LBUTTONDOWN, WM_MOUSEWHEEL, WM_KEYDOWN, WM_CHAR, WM_SETFOCUS and similar messages, and writes them into ImGuiIO. It returns non-zero only for the few messages it handles completely (such as WM_SETCURSOR when ImGui sets the mouse cursor). Then we return immediately. For everything else your normal switch runs as before.

Is it safe before ImGui is initialised?

Yes. CreateWindowEx() sends WM_CREATE, WM_SIZE and more before initialize() runs. The handler checks for a missing ImGui context and simply returns 0.

3. Initialise ImGui after the GL context

    // Make rendering context current
    if (wglMakeCurrent(ghdc, ghrc) == FALSE) { ... return (-5); }
    ...
    glEnable(GL_DEPTH_TEST);
    glDepthFunc(GL_LEQUAL);

//================================IMGUI==============================================
    // ImGui must be initialized AFTER the OpenGL context is created
    IMGUI_initialize();
    g_ImGuiInitialized = true;
//===================================================================================

The OpenGL2 backend makes real GL calls. It creates the font-atlas texture on the first NewFrame, and draws and deletes textures later. The simple rule is that ImGui's lifetime sits inside the GL context's lifetime: start it after wglMakeCurrent and end it before wglDeleteContext. The body, from the bottom of the file:

void IMGUI_initialize(void)
{
    // Setup Dear ImGui context
    IMGUI_CHECKVERSION();
    ImGui::CreateContext();

    // Setup Dear ImGui style
    ImGui::StyleColorsDark();

    // Setup Platform/Renderer backends
    ImGui_ImplWin32_InitForOpenGL(ghwnd);   // Win32  : input, mouse, keyboard
    ImGui_ImplOpenGL2_Init();               // OpenGL : draws the ImGui windows
}
CallPurpose
IMGUI_CHECKVERSION()Asserts that the header and compiled imgui.cpp match, which catches mixed versions.
ImGui::CreateContext()Allocates all of ImGui's state, including ImGuiIO. Call nothing else in ImGui before this.
ImGui::StyleColorsDark()Picks the colour theme (also StyleColorsLight / StyleColorsClassic).
ImGui_ImplWin32_InitForOpenGL(ghwnd)Platform backend: remembers the HWND and sets up timing, cursor and key mapping.
ImGui_ImplOpenGL2_Init()Renderer backend: prepares to draw with fixed-function GL.
Optional extras you will see in real projects 
ImGuiIO &io = ImGui::GetIO();
io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;   // Tab / arrow keys move between widgets
io.IniFilename = NULL;                                  // don't save window layout to imgui.ini

Put these right after CreateContext(). The ImGui Lab engine sets IniFilename = NULL but leaves keyboard navigation off: with navigation on, io.WantCaptureKeyboard stays true whenever any ImGui window has focus, which would block the WASD camera keys. The starter keeps the default, so it writes an imgui.ini next to the exe that remembers window positions between runs.

4. Draw the UI every frame, before SwapBuffers

void display(void)
{
//================================IMGUI==============================================
    // Background color comes from the ImGui color editor
    glClearColor(gClearColor[0], gClearColor[1], gClearColor[2], 1.0f);
//===================================================================================
    glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);

    ... your normal triangle drawing ...

//================================IMGUI==============================================
    // Draw ImGui on top of the scene, just before SwapBuffers
    IMGUI_display();
//===================================================================================

    SwapBuffers(ghdc);
}

The first banner shows how ImGui connects to your scene: glClearColor now reads a variable that the UI edits. The second one draws the UI last, so it sits on top of the 3D scene, and before SwapBuffers, so it's in the same frame.

void IMGUI_display(void)
{
    // Start the Dear ImGui frame
    ImGui_ImplOpenGL2_NewFrame();
    ImGui_ImplWin32_NewFrame();
    ImGui::NewFrame();

    // Our UI : one window with a text, a color editor and a checkbox
    ImGui::Begin("Hello, ImGui!");
    ImGui::Text("This is my first ImGui window");
    ImGui::ColorEdit3("Background", gClearColor);
    ImGui::Checkbox("Rotate triangle", &gRotate);
    ImGui::End();

    // Rendering
    ImGui::Render();
    ImGui_ImplOpenGL2_RenderDrawData(ImGui::GetDrawData());
}
  1. Three NewFrame calls, in this order: renderer backend (creates the font texture on the first frame), platform backend (updates io.DisplaySize, io.DeltaTime, mouse position), then ImGui::NewFrame() (starts a fresh UI frame).
  2. Your UI code. Any number of Begin/End windows. In ImGui Lab, this is exactly where Lesson_UI() is called.
  3. ImGui::Render() finalises the frame into ImDrawData (vertex and index buffers). It doesn't call OpenGL.
  4. ImGui_ImplOpenGL2_RenderDrawData() issues the actual GL calls.

5. Shut down before the GL context dies

void uninitialize(void)
{
//================================IMGUI==============================================
    // Shutdown ImGui BEFORE the OpenGL context is deleted
    IMGUI_uninitialize();
//===================================================================================

    ... wglMakeCurrent(NULL, NULL); wglDeleteContext(ghrc); ReleaseDC(...); ...
}

void IMGUI_uninitialize(void)
{
    if (g_ImGuiInitialized)
    {
        ImGui_ImplOpenGL2_Shutdown();
        ImGui_ImplWin32_Shutdown();
        ImGui::DestroyContext();
        g_ImGuiInitialized = false;
    }
}

This is the reverse of initialisation: renderer, then platform, then context. ImGui_ImplOpenGL2_Shutdown() deletes the font texture with glDeleteTextures, so the context must still be current. The g_ImGuiInitialized flag makes this safe when initialize() failed early and ImGui was never created.

Game-engine angle

Keeping ImGui inside three functions with banners around every call site is a good habit for a real engine. The editor layer then stays separate from the runtime. Some engines compile those functions out entirely in shipping builds (#ifdef EDITOR), and the game runs exactly the same without them.

Building: run.bat

cl.exe /c /EHsc /std:c++17 /TP /I external/imgui ^
    OGL.c ^
    external/imgui/imgui.cpp ^

    external/imgui/imgui_impl_win32.cpp ^
    /Fo"intermediate\\"

link.exe intermediate\OGL.obj intermediate\imgui.obj intermediate\imgui_demo.obj ^
    intermediate\imgui_draw.obj intermediate\imgui_widgets.obj intermediate\imgui_tables.obj ^
    intermediate\imgui_impl_opengl2.obj intermediate\imgui_impl_win32.obj ^
    User32.lib GDI32.lib OpenGL32.lib ^
    /SUBSYSTEM:WINDOWS /OUT:bin\OGL.exe

bin\OGL.exe
PartWhy
/cCompile only. Each .cpp becomes an .obj in intermediate\ (/Fo).
/TPTreat all files as C++, including OGL.c. ImGui uses namespaces, references and default arguments, so a C compile of OGL.c would fail on #include "imgui.h".
/EHsc /std:c++17Standard C++ exception model and language version.
/I external/imguiSo #include "imgui.h" is found.
7 ImGui .cpp files4 core files + the demo (needed for ShowDemoWindow) + 2 backends.
User32 GDI32 OpenGL32Windows, pixel formats and GL. The Win32 backend loads XInput dynamically, so no extra lib is needed.
/SUBSYSTEM:WINDOWSUses WinMain and opens no console window.

Run it from the x64 Native Tools Command Prompt for VS 2022 so that cl.exe and link.exe are on the PATH. ImGui Lab does the same thing, except that it compiles ImGui only once and caches the .obj files, which is why your builds take about a second.

Common pitfalls

SymptomCause and fix
UI draws, but you can't click or type anythingThe WndProc forwarding (banner 2) is missing, or it's in a different window's WndProc.
Crash or assert on the first ImGui callAn ImGui function was called before CreateContext(), e.g. ImGui::GetIO() in WM_SIZE during CreateWindowEx. Guard with your init flag.
Nothing visible, no errorsIMGUI_display() is called after SwapBuffers, or RenderDrawData is missing.
Text is solid blocks or missingNo GL context was current when the backend created the font texture on the first frame (for example, ImGui was started before wglMakeCurrent and a frame ran early, or the context was made current on another thread).
UI tinted, foggy or textured strangelyLeftover fixed-function state that the backend doesn't reset, for example GL_FOG, GL_TEXTURE_GEN_S/T, a bound VBO or a glUseProgram shader. Disable those after drawing your scene.
Pressing Esc while typing quits the appYour own key handling ignores io.WantCaptureKeyboard (see challenge 2).
Crash on exitImGui was shut down after wglDeleteContext. Keep banner 5 first in uninitialize().
What about wireframe?

If your scene uses glPolygonMode(GL_FRONT_AND_BACK, GL_LINE), the current OpenGL2 backend saves it, switches to GL_FILL for the UI and restores it afterwards. It also handles depth test, lighting, culling, blending, viewport and matrices. Older backends and hand-written renderers often didn't, which is why resetting GL_FILL after your scene is still a good habit. The engine does it, and you can test it with the Wireframe scene checkbox.

The example code

The engine has already done all of the above, so the code on the right uses the integration directly. It shows the ImGui version and backends, and has toggles for the three built-in tool windows:

  • ImGui::ShowDemoWindow(): the reference. Every widget and flag is demonstrated, and the source is in imgui_demo.cpp. When you wonder "can ImGui do X?", look here first.
  • ImGui::ShowMetricsWindow(): windows, draw calls, vertices, and an Item Picker.
  • ImGui::ShowAboutWindow(): version and build configuration.

Spend ten minutes in the Demo window. Open Widgets, Layout, Tables and Tools, and in Configuration try the style editor.

Challenges

  1. In the Demo window, find Widgets > Basic and Widgets > Plotting. Then search imgui_demo.cpp for "Plotting" to see the code behind it.
  2. In the starter OGL.c, Esc quits even while you're typing in an ImGui widget. Fix WM_KEYDOWN so it ignores keys when ImGui wants the keyboard.
  3. In the starter, add io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard; to IMGUI_initialize() and a SliderFloat for a new gSpeed variable used in update() instead of the fixed 0.05f.
