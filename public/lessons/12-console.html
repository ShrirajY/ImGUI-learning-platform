Why every engine has a console

A console does two jobs. It is the output of the engine: every log message, warning and error, in one searchable place. It is also an input: a command line that reaches any system without building a UI for it (spawn an object, change the time scale, toggle debug drawing). Quake made it famous. Unreal, Source and most in-house engines still ship one.

Reading the engine log

The engine keeps the last 512 lines in a ring buffer. You don't touch the ring directly. Index 0 is always the oldest line:

struct LogLine { int level; float time; char text[240]; };   // level: LOG_INFO / LOG_WARN / LOG_ERROR

int count = Engine_GetLogCount();
for (int i = 0; i < count; i++)
{
    const LogLine *l = Engine_GetLog(i);
    ImGui::TextUnformatted(l->text);         // never Text(l->text): lines may contain '%'
}

Writing is just Engine_Log, Engine_LogWarn and Engine_LogError, all printf-style. Remember that rule when you echo user input: Engine_Log("> %s", input), never Engine_Log(input).

Colour by level

bool hasCol = true; ImVec4 col;
if      (l->level == LOG_ERROR) col = ImVec4(1.0f, 0.4f, 0.4f, 1.0f);
else if (l->level == LOG_WARN)  col = ImVec4(1.0f, 0.8f, 0.3f, 1.0f);
else hasCol = false;

if (hasCol) ImGui::PushStyleColor(ImGuiCol_Text, col);
ImGui::TextUnformatted(l->text);
if (hasCol) ImGui::PopStyleColor();

TextColored would also work, but it takes a format string, so you would have to write TextColored(col, "%s", text). Push/Pop with TextUnformatted is the faster and safer pattern for raw text.

Filtering

Two independent filters, both applied with continue in the loop:

  • Level checkboxes: static bool showLevel[3], indexed by l->level. The labels show live counts using "Warn (%d)###warn". The part after ### is the ID, so the checkbox keeps its identity while the number changes.
  • Text search: ImGuiTextFilter from lesson 8. filter.Draw() draws the input and filter.PassFilter(l->text) tests each line. Try spawn,-error.

Layout: scrolling region + reserved footer

The log must scroll while the input line stays pinned at the bottom. Put the log in a child whose height is negative: "fill everything except this many pixels".

const float footer = ImGui::GetStyle().ItemSpacing.y + ImGui::GetFrameHeightWithSpacing();
if (ImGui::BeginChild("LogRegion", ImVec2(0, -footer), ImGuiChildFlags_None, ImGuiWindowFlags_HorizontalScrollbar))
{
    // ... lines ...
}
ImGui::EndChild();
ImGui::Separator();
ImGui::InputText("##cmd", ...);    // fits exactly in the reserved space

GetFrameHeightWithSpacing() is the height of one framed widget (an InputText) plus the spacing under it. The extra ItemSpacing.y covers the separator.

Auto-scroll that respects the user

// at the END of the child's contents:
if (scrollToBottom || (autoScroll && ImGui::GetScrollY() >= ImGui::GetScrollMaxY()))
    ImGui::SetScrollHereY(1.0f);    // 1.0 = put the current cursor position at the bottom edge
scrollToBottom = false;

Only follow new lines if the view was already at the bottom. If the user scrolled up to read an error, new spam must not yank them back down. The scrollToBottom flag forces one jump after the user runs a command, because they want to see the result.

The command line

bool reclaimFocus = false;
ImGuiInputTextFlags flags = ImGuiInputTextFlags_EnterReturnsTrue | ImGuiInputTextFlags_EscapeClearsAll
                          | ImGuiInputTextFlags_CallbackHistory  | ImGuiInputTextFlags_CallbackCompletion;
ImGui::SetNextItemWidth(-FLT_MIN);
if (ImGui::InputText("##cmd", input, sizeof(input), flags, ConsoleCallback))
{
    Execute(input);
    input[0] = 0;
    reclaimFocus = true;
}
ImGui::SetItemDefaultFocus();              // focus the input when the window first appears
if (reclaimFocus)
    ImGui::SetKeyboardFocusHere(-1);       // -1 = re-focus the widget we just drew
PieceWhy
EnterReturnsTrueNormally InputText returns true on every edit. With this flag it returns true only when Enter is pressed, which is what a command line wants
SetKeyboardFocusHere(-1)Pressing Enter deactivates the field. Without this, you'd have to click it again for every command
EscapeClearsAllEsc empties the line (the default behaviour is "revert")
CallbackHistory / CallbackCompletionCall your function on Up/Down and on Tab

A tiny command parser

No need for anything fancy: trim the line, split off the first word, and compare it with _stricmp (case-insensitive). The rest of the line is the arguments. That lets spawn sphere Big Moon use "Big Moon" (with a space) as the name.

char *args = buf;
while (*args && *args != ' ') args++;
if (*args) { *args = 0; args++; }           // buf = "spawn", args = "sphere Big Moon"

if      (_stricmp(buf, "timescale") == 0) gTimeScale = (float)atof(args);
else if (_stricmp(buf, "grid") == 0)      gShowGrid  = ParseOnOff(args, gShowGrid);
else Engine_LogError("Unknown command '%s'. Type 'help'.", buf);

Supported in the lesson: help, clear, list, spawn <mesh> [name], delete <name>, select <name>, focus, timescale <x>, pause/grid/wireframe [on|off], reset.

Report errors through the log

A bad argument should produce a red line that says what was expected, for example spawn: unknown mesh 'cub' (try: spawn cube). Users learn the commands from the error messages.

History with an InputText callback

With CallbackHistory, ImGui calls your function when Up or Down is pressed in the field. You get an ImGuiInputTextCallbackData* that lets you edit the text safely:

static int ConsoleCallback(ImGuiInputTextCallbackData *data)
{
    if (data->EventFlag == ImGuiInputTextFlags_CallbackHistory)
    {
        int prev = historyPos;
        if (data->EventKey == ImGuiKey_UpArrow)
        {
            if (historyPos == -1)    historyPos = historyCount - 1;   // jump to newest
            else if (historyPos > 0) historyPos--;
        }
        else if (data->EventKey == ImGuiKey_DownArrow)
        {
            if (historyPos != -1 && ++historyPos >= historyCount) historyPos = -1;
        }
        if (prev != historyPos)
        {
            data->DeleteChars(0, data->BufTextLen);                 // replace the whole line
            if (historyPos >= 0) data->InsertChars(0, history[historyPos]);
        }
    }
    return 0;
}
Edit through the callback, not your buffer

While the InputText is active, it keeps its own copy of the text. If you strcpy into your input[] array from outside, the widget will overwrite it next frame. Inside the callback, use DeleteChars and InsertChars. They update the buffer, length, cursor and the widget's internal state together.

Tab completion uses the same callback with EventFlag == ImGuiInputTextFlags_CallbackCompletion. The lesson completes the command name when there's exactly one match, and prints the candidates when there are several.

Game-engine angle

Today the parser is a chain of if/else. In a growing engine you would turn it into a command registry: a table of { name, help, function pointer } that any subsystem can add to at start-up (RegisterCommand("r_wireframe", ...)). The same registry then drives help, Tab completion and even a cheat menu. Add console variables ("cvars") that bind a name to a float* or bool*, and the console can tweak any setting in the engine without new UI.
