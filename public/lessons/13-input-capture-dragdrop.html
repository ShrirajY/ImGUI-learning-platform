One mouse, two consumers

Your engine and ImGui both want the same mouse and keyboard. When the user right-drags over the Inspector, they mean to scroll or edit, not to orbit the camera. When they press W inside a text field, they are typing, not moving forward. ImGui solves this with two flags it recomputes every frame:

FlagTrue when...Your engine should...
io.WantCaptureMousethe mouse is over an ImGui window, or a drag that started in ImGui is still goingskip camera orbit, picking and wheel zoom
io.WantCaptureKeyboardan item that takes keyboard input is active (e.g. a text field) or a modal is open. If you enable ImGuiConfigFlags_NavEnableKeyboard, it is also true whenever any ImGui window has focus, which is why the ImGui Lab engine leaves keyboard navigation offskip WASD, hotkeys and gameplay keys
io.WantTextInputa text field is being editeddefinitely don't treat keys as commands
"Why does WASD stop working after I click a window?"

With keyboard navigation enabled, a focused ImGui window owns the keyboard, so arrow keys and Tab can move between widgets. Click empty space in the 3D view and ImGui drops focus, giving the keyboard back to the engine. Watch the Input State window while you try it. For editor hotkeys that should work while a panel is focused but not while typing (like Ctrl+D), test !io.WantTextInput instead. The capstone lesson does exactly that.

That is exactly what the mini engine does in UpdateCamera() in OGL.c:

static void UpdateCamera(float dt)
{
    ImGuiIO &io = ImGui::GetIO();
    if (!io.WantCaptureMouse)            // the mouse belongs to the 3D view
    {
        if (ImGui::IsMouseDragging(ImGuiMouseButton_Right, 0.0f)) { /* orbit */ }
        if (io.MouseWheel != 0.0f)                                { /* zoom  */ }
        if (gEnablePicking && ImGui::IsMouseClicked(ImGuiMouseButton_Left))
            gSelectedEntity = PickEntity(io.MousePos.x, io.MousePos.y);
    }
    if (!io.WantCaptureKeyboard)         // the keyboard belongs to the game
    {
        if (ImGui::IsKeyDown(ImGuiKey_W)) { /* move forward */ }
        ...
    }
}

The same check sits in WndProc before ESC quits the app, so pressing ESC to cancel a text edit doesn't close the window.

Why the engine runs UpdateCamera AFTER Lesson_UI

WantCaptureMouse is decided from which windows exist and where they are. Calling the camera code after your UI is submitted means the flags describe this frame's layout. Order it the other way round and a click on a window that just opened could fall through and select an entity behind it.

Don't use IsWindowHovered() for this

IsWindowHovered() only tells you about the current window. Use the io.WantCapture* flags to decide whether input goes to ImGui or the engine. They also handle popups, active drags and keyboard focus.

Asking about the last item

Every widget becomes the "last item", and a set of query functions describes how the user is interacting with it. Call them right after the widget:

FunctionMeaning
IsItemHovered()mouse is over it (and not blocked by a popup)
IsItemActive()being held or edited right now; true every frame of a drag
IsItemClicked(button)hovered and clicked this frame; works on any item, any button
IsItemDeactivatedAfterEdit()user just finished editing (great for undo)
IsWindowHovered() / IsWindowFocused()same idea for the current window
if (ImGui::Selectable(e->name, gSelectedEntity == i))
    gSelectedEntity = i;
if (ImGui::IsItemHovered() && ImGui::IsMouseDoubleClicked(ImGuiMouseButton_Left))
    Engine_FocusEntity(i);           // double-click a row = frame it in the 3D view

Raw mouse and keys

  • io.MousePos, io.MouseDelta, io.MouseDown[0..4], io.MouseWheel give you the raw mouse state in screen pixels.
  • ImGui::IsKeyPressed(ImGuiKey_F, false) is true for one frame. Pass false to ignore auto-repeat. IsKeyDown is true while the key is held.
  • ImGui::IsKeyChordPressed(ImGuiMod_Ctrl | ImGuiKey_D) handles modifier combos.
if (!io.WantCaptureKeyboard && ImGui::IsKeyPressed(ImGuiKey_Delete, false) && gSelectedEntity >= 0)
    Engine_RemoveEntity(gSelectedEntity);   // editor hotkey that is silent while typing

InvisibleButton: your own interactive area

InvisibleButton(id, size) takes up layout space and behaves like a button (hover, active, click), but draws nothing. Put it down, query it, then draw whatever you like on top with the draw list (lesson 15 covers this properly). This is how you make touch pads, timelines, curve editors and viewport widgets:

ImVec2 p = ImGui::GetCursorScreenPos();
ImGui::InvisibleButton("##pad", ImVec2(200, 70));
if (ImGui::IsItemActive())                                     // held down
    gEntities[gSelectedEntity].rotation[1] += io.MouseDelta.x;  // drag to rotate
ImGui::GetWindowDrawList()->AddRectFilled(p, ImVec2(p.x + 200, p.y + 70), IM_COL32(80, 160, 255, 60));

While the invisible button is held, WantCaptureMouse stays true even if the cursor leaves the window. The camera won't suddenly start orbiting halfway through your drag.

Drag and drop

ImGui's drag and drop needs only two small blocks of code. A source goes right after the item you drag from, and a target goes right after the item you drop onto. They are matched by a payload type string:

ImGui::Button(gMeshNames[m]);
if (ImGui::BeginDragDropSource())                       // true while this item is dragged
{
    ImGui::SetDragDropPayload("MESH_TYPE", &m, sizeof(int));  // ImGui COPIES the bytes
    ImGui::Text("Mesh: %s", gMeshNames[m]);             // anything here = drag tooltip
    ImGui::EndDragDropSource();
}
ImGui::Selectable(e->name, selected);
if (ImGui::BeginDragDropTarget())                       // true while something hovers it
{
    if (const ImGuiPayload *p = ImGui::AcceptDragDropPayload("MESH_TYPE"))
        e->mesh = *(const int *)p->Data;                // only on mouse release
    ImGui::EndDragDropTarget();
}
  • Payload types are strings of up to 32 characters. A target only lights up for types it accepts, so "MESH_TYPE" can never be dropped where you expect an "ENTITY_INDEX".
  • Payload data is copied. Send small values (indices, IDs, handles), not pointers into arrays that might move.
  • A target can call AcceptDragDropPayload several times with different types.
  • ImGui::GetDragDropPayload() lets any code peek at what is being dragged. The lesson uses it to highlight the spawn zone while a mesh is in flight.

Built-in colour payloads

ColorButton, ColorEdit3/4 and ColorPicker are already drag sources and drop targets. They use the reserved types IMGUI_PAYLOAD_TYPE_COLOR_3F ("_COL3F", float[3]) and IMGUI_PAYLOAD_TYPE_COLOR_4F ("_COL4F", float[4]). Accept those in your own targets and any colour widget in your editor can paint entities:

if (const ImGuiPayload *p = ImGui::AcceptDragDropPayload(IMGUI_PAYLOAD_TYPE_COLOR_4F))
    memcpy(e->color, p->Data, sizeof(float) * 4);

Drag to reorder

Make each row both a source and a target of "ENTITY_INDEX". On drop, record the move and apply it after the loop. Shuffling the array while you are still drawing it would give you a frame of mixed-up rows and stale IDs.

static int moveFrom = -1, moveTo = -1;
for (int i = 0; i < gEntityCount; i++)
{
    ImGui::PushID(i);
    ImGui::Selectable(gEntities[i].name);
    if (ImGui::BeginDragDropSource()) { ImGui::SetDragDropPayload("ENTITY_INDEX", &i, sizeof(int)); ImGui::EndDragDropSource(); }
    if (ImGui::BeginDragDropTarget())
    {
        if (const ImGuiPayload *p = ImGui::AcceptDragDropPayload("ENTITY_INDEX"))
        { moveFrom = *(const int *)p->Data; moveTo = i; }
        ImGui::EndDragDropTarget();
    }
    ImGui::PopID();
}
if (moveFrom >= 0) { MoveEntity(moveFrom, moveTo); moveFrom = moveTo = -1; }
Only call EndDragDrop* if Begin returned true

Unlike Begin()/End() for windows, EndDragDropSource() and EndDragDropTarget() must only be called inside the if.

Game-engine angle

Drag and drop is how most editor work gets done. You drag a mesh from the content browser into the scene, a material onto a model, a prefab into the hierarchy to parent it, or a sound onto a component slot. Name your payload types after your engine's asset types ("ASSET_MESH", "ASSET_TEXTURE", "ENTITY_ID") and send stable IDs or GUIDs, never raw pointers. The input-capture rule matters just as much: an editor where the camera spins while you drag a slider gets abandoned quickly. Route all of your engine's input through one place that checks WantCaptureMouse/Keyboard.
