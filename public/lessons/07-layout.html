How ImGui places widgets

ImGui keeps a cursor for every window, much like a text cursor. Each widget is drawn at the cursor, then the cursor moves down to the next line. All layout functions do one of three things: move the cursor, change how wide the next widgets are, or open a new region (group, child, table, tab) with its own cursor.

There is no layout pass and no retained tree of boxes. The order of your function calls is the layout. Once that clicks, layout becomes very predictable.

Lines: SameLine, Spacing, Separator, Dummy

ImGui::Button("Play");  ImGui::SameLine();         // next widget goes to the right
ImGui::Button("Pause"); ImGui::SameLine(0, 20);    // offset 0 = "right after", spacing 20 px
ImGui::Button("Stop");

ImGui::Text("Name");    ImGui::SameLine(100);      // absolute x = 100 inside the window
ImGui::Text("%s", e->name);

ImGui::Spacing();                                  // small vertical gap (ItemSpacing.y)
ImGui::Dummy(ImVec2(0, 12));                       // invisible item of an exact size
ImGui::Separator();                                // full-width line
CallMeaning
SameLine()Next item on the same line, default spacing
SameLine(0, s)Same line, exactly s pixels after the previous item
SameLine(x)Same line, starting at window-local x position x. Great for aligning a column of values.
Dummy(size)Reserves space without drawing anything. Use it as a spacer or to push things around.
NewLine()Undo a pending SameLine / force an empty line

Indentation and groups

ImGui::Text("Transform");
ImGui::Indent();                       // default = style.IndentSpacing (21 px)
    ImGui::DragFloat3("Position", e->position, 0.05f);
ImGui::Unindent();                     // always balance Indent/Unindent

ImGui::BeginGroup();                   // everything until EndGroup becomes ONE item
    ImGui::Button("Add");
    ImGui::Button("Remove");
ImGui::EndGroup();
ImGui::SameLine();                     // ...so this goes to the right of the whole group
ImGui::BeginGroup();
    ImGui::Text("Entities: %d", gEntityCount);
    ImGui::Text("Selected: %d", gSelectedEntity);
ImGui::EndGroup();
if (ImGui::IsItemHovered()) ImGui::SetTooltip("Hovering the whole group");

A group locks the starting X position, then measures its bounding box. After EndGroup(), the group behaves like a single widget, so SameLine(), IsItemHovered() and tooltips work on the whole block. That is how you build a column of buttons beside a column of stats.

Widths: SetNextItemWidth, PushItemWidth, GetContentRegionAvail

By default, sliders and inputs take about 65% of the window width and the label goes in the remaining space on the right. In an editor you usually want more control:

ImGui::SetNextItemWidth(120);                       // only the next widget
ImGui::DragFloat("Speed", &gCamera.moveSpeed);

ImGui::PushItemWidth(-100);                         // all following widgets: leave 100 px for labels
ImGui::SliderFloat("FOV", &gCamera.fov, 20, 120);
ImGui::DragFloat("Distance", &gCamera.distance);
ImGui::PopItemWidth();

ImVec2 avail = ImGui::GetContentRegionAvail();      // space left from the cursor to the edges
float half = (avail.x - ImGui::GetStyle().ItemSpacing.x) * 0.5f;
ImGui::Button("Reset", ImVec2(half, 0)); ImGui::SameLine();
ImGui::Button("Clear", ImVec2(half, 0));            // two buttons that exactly fill the row
Width rules

A positive width is in pixels. A negative width means "stop this many pixels before the right edge". -FLT_MIN means "all the way to the right edge" and is the idiom for full-width widgets, especially inside tables. GetContentRegionAvail() is your best friend for anything proportional.

Child regions: BeginChild

A child is a scrollable sub-window inside your window. Use it for lists that should scroll on their own while the buttons above them stay put.

// size.x = 0 -> full width, size.y = 150 -> fixed height. Negative = "leave this much space".
if (ImGui::BeginChild("EntityList", ImVec2(0, 150), ImGuiChildFlags_Borders | ImGuiChildFlags_ResizeY))
{
    for (int i = 0; i < gEntityCount; i++)
        ImGui::Text("%s", gEntities[i].name);
}
ImGui::EndChild();   // ALWAYS, like End()
ImGuiChildFlags_Effect
BordersDraw a border and add window padding (renamed from Border in 1.91.1)
AlwaysUseWindowPaddingPadding even without a border
ResizeX / ResizeYUser can drag the right / bottom edge to resize
AutoResizeX / AutoResizeYSize to fit the contents
FrameStyleLook like a framed widget (this is how ListBox is made)
Old code alert

Before 1.90, the third argument was bool border. You will still see BeginChild("x", size, true) in tutorials. It still compiles because ImGuiChildFlags_Borders == 1, but window flags like ImGuiWindowFlags_AlwaysUseWindowPadding moved into the new child flags. Write new code with ImGuiChildFlags_*.

Collapsing headers and tree nodes

if (ImGui::CollapsingHeader("Transform", ImGuiTreeNodeFlags_DefaultOpen))
{
    // no TreePop needed, no extra indent
    ImGui::DragFloat3("Position", e->position, 0.05f);
}

if (ImGui::TreeNode("Advanced"))      // indents and pushes an ID
{
    ImGui::Checkbox("Spin", &e->spin);
    ImGui::TreePop();                  // ONLY if TreeNode returned true
}

CollapsingHeader is the big framed section bar you see in every Inspector. TreeNode is the lighter, indented version used for nested data. ImGui remembers the open/closed state for you (it is keyed on the label's ID).

Tab bars

if (ImGui::BeginTabBar("InspectorTabs"))
{
    if (ImGui::BeginTabItem("Camera"))  { /* camera widgets */ ImGui::EndTabItem(); }
    if (ImGui::BeginTabItem("Lighting")){ /* light widgets  */ ImGui::EndTabItem(); }
    ImGui::EndTabBar();                // only if BeginTabBar returned true
}

Only the selected tab's contents are submitted each frame, so tabs are also a cheap way to hide expensive UI. Add ImGuiTabBarFlags_Reorderable to let the user drag tabs around.

The property grid

Every engine Inspector (Unity, Unreal, Godot) uses the same look: label on the left, widget on the right, all widgets left-aligned on one vertical line and stretching to the edge. ImGui's default puts the label on the right, so we build the grid ourselves. A 2-column table is the cleanest way:

Inspector
Field of view45.0
Distance12.0
Show grid✓
static void L07_PropRow(const char *label)
{
    ImGui::TableNextRow();
    ImGui::TableNextColumn();
    ImGui::AlignTextToFramePadding();   // line the text up with the framed widget
    ImGui::TextUnformatted(label);
    ImGui::TableNextColumn();
    ImGui::SetNextItemWidth(-FLT_MIN);  // widget fills the value column
}

if (ImGui::BeginTable("##props", 2, ImGuiTableFlags_SizingStretchProp))
{
    ImGui::TableSetupColumn("Name",  ImGuiTableColumnFlags_WidthFixed, 110.0f);
    ImGui::TableSetupColumn("Value", ImGuiTableColumnFlags_WidthStretch);

    L07_PropRow("Field of view"); ImGui::SliderFloat("##fov", &gCamera.fov, 20, 120, "%.0f deg");
    L07_PropRow("Distance");      ImGui::DragFloat("##dist", &gCamera.distance, 0.1f, 1, 200);
    ImGui::EndTable();
}

Note the ## labels. Text after ## is not shown, but it is still part of the widget's ID. That lets us hide the built-in label while keeping every widget unique.

No table? Use SameLine(offset)

For quick panels, ImGui::AlignTextToFramePadding(); ImGui::Text("FOV"); ImGui::SameLine(110); ImGui::SetNextItemWidth(-FLT_MIN); ImGui::SliderFloat("##fov", ...) gives the same look. The table version adapts better to fonts and DPI, and the user can resize the label column if you add ImGuiTableFlags_Resizable.

Game-engine angle

The code for this lesson is the skeleton of a real Inspector: tabs for broad areas (Scene, Camera, Lighting, Render), collapsing headers for sections, and a property grid helper used everywhere. Write the helper once and every panel in your editor gets a consistent look. Later lessons (Hierarchy, Inspector) reuse this exact pattern.
