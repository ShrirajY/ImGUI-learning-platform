You've built an editor. What now?

The capstone runs on the master branch of Dear ImGui with the fixed-function OpenGL2 backend, in a single Win32 window. That's a good place to learn. A production engine editor usually adds docking, a modern renderer backend, a "Game View" render target and a few battle-tested extensions. This page is a map of those next steps.

Docking: the docking branch

Dockable tabs and splitters (dragging the Inspector onto the right edge and having it snap there) are not in this version. They live on the official docking branch, which is kept in sync with master and is used by most engine editors.

Switching

  1. Download the docking branch (git clone -b docking https://github.com/ocornut/imgui, or "Download ZIP" on GitHub with the docking branch selected).
  2. Replace all core files together: imgui.cpp/.h, imgui_internal.h, imgui_draw.cpp, imgui_widgets.cpp, imgui_tables.cpp, imgui_demo.cpp, imconfig.h, imstb_*.h, and the backends you use (imgui_impl_win32.*, imgui_impl_opengl2.*). Mixing versions causes compile errors or crashes.
  3. Enable it and add a dockspace:
// after CreateContext()
ImGuiIO &io = ImGui::GetIO();
io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;

// every frame, before your panels (docking branch only!)
ImGui::DockSpaceOverViewport(0, ImGui::GetMainViewport(), ImGuiDockNodeFlags_PassthruCentralNode);
// PassthruCentralNode: the empty central area is transparent, so your 3D scene shows through

Your existing Begin()/End() panels become dockable with no other changes. Drag a window by its title bar onto another window or the dockspace to dock it. Set io.ConfigDockingWithShift = true if you'd rather require Shift for docking. For a predefined layout, look at the DockBuilder* functions in imgui_internal.h (DockBuilderSplitNode, DockBuilderDockWindow).

Multi-viewports

Also on the docking branch: io.ConfigFlags |= ImGuiConfigFlags_ViewportsEnable lets windows be dragged outside the main OS window, becoming real OS windows (great on multi-monitor setups). It needs extra backend support: call ImGui::UpdatePlatformWindows() and ImGui::RenderPlatformWindowsDefault() after rendering, and the Win32+OpenGL setup needs per-window HDC handling. See the example_win32_opengl3 sample on that branch for the exact code.

Modern OpenGL: the OpenGL3 backend

If your engine moves from fixed-function GL to shaders and VBOs, switch the renderer backend from imgui_impl_opengl2 to imgui_impl_opengl3:

#include "imgui_impl_opengl3.h"

ImGui_ImplWin32_InitForOpenGL(hwnd);
ImGui_ImplOpenGL3_Init("#version 130");      // GLSL version string matching your context

// per frame
ImGui_ImplOpenGL3_NewFrame();
ImGui_ImplWin32_NewFrame();
ImGui::NewFrame();
...
ImGui::Render();
ImGui_ImplOpenGL3_RenderDrawData(ImGui::GetDrawData());
  • It renders with a shader + VBO, so it works in a core profile context (created with wglCreateContextAttribsARB).
  • It ships with its own minimal loader (imgui_impl_opengl3_loader.h), so it works even before you add GLAD/GLEW. If your engine already uses a loader, that's fine too.
  • It saves and restores the GL state it touches, so it slots in after your scene rendering like the GL2 backend does.
  • ImTextureID is still a cast GLuint, so everything from lesson 16 carries over unchanged.

The "Game View": scene in an ImGui window

Right now the 3D scene fills the whole OS window and panels float on top. Most editors instead render the scene into an offscreen framebuffer (FBO) and display its colour texture with ImGui::Image, so the viewport becomes a dockable panel like any other:

// once (GL 3.0+ or ARB_framebuffer_object): FBO with a colour texture + depth renderbuffer
glGenFramebuffers(1, &fbo);    glBindFramebuffer(GL_FRAMEBUFFER, fbo);
glGenTextures(1, &colorTex);   /* glTexImage2D(..., w, h, ...) */
glFramebufferTexture2D(GL_FRAMEBUFFER, GL_COLOR_ATTACHMENT0, GL_TEXTURE_2D, colorTex, 0);
glGenRenderbuffers(1, &depthRb); /* glRenderbufferStorage(GL_RENDERBUFFER, GL_DEPTH_COMPONENT24, w, h) */
glFramebufferRenderbuffer(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_RENDERBUFFER, depthRb);

// every frame, inside your "Scene" window
ImVec2 size = ImGui::GetContentRegionAvail();
if (size.x != fboW || size.y != fboH) ResizeFbo((int)size.x, (int)size.y);   // match the panel
// ... render the scene into the FBO (bind fbo, glViewport(0,0,w,h), draw, bind 0) ...
ImGui::Image((ImTextureID)(intptr_t)colorTex, size, ImVec2(0, 1), ImVec2(1, 0)); // flipped V!
bool viewportHovered = ImGui::IsItemHovered();   // replaces io.WantCaptureMouse for camera input
Two gotchas
  • Flip V: OpenGL render targets have their origin at the bottom-left, so pass uv0=(0,1), uv1=(1,0).
  • Input and picking change: camera controls should check IsItemHovered() on the image instead of WantCaptureMouse (the mouse is over an ImGui window now). Picking must convert the mouse position to image-local coordinates with GetItemRectMin().

With fixed-function GL on Windows, glGenFramebuffers isn't in the GL 1.1 headers, so load it with wglGetProcAddress (OGL.c does the same for wglSwapIntervalEXT), or use a loader such as GLAD.

Saving the layout: imgui.ini

OGL.c sets io.IniFilename = NULL so every lesson starts fresh. In your editor, you want the opposite: window positions, sizes, collapsed state, table column widths (and dock layout on the docking branch) restored on every launch.

io.IniFilename = "editor_layout.ini";     // default is "imgui.ini" in the working directory

// or manage it yourself, e.g. to store it in your project file or user profile:
io.IniFilename = NULL;
ImGui::LoadIniSettingsFromMemory(savedText, savedSize);   // before the first NewFrame
...
if (io.WantSaveIniSettings)                               // ImGui says something changed
{
    size_t size;
    const char *ini = ImGui::SaveIniSettingsToMemory(&size);
    WriteToMyConfig(ini, size);
    io.WantSaveIniSettings = false;
}

This is when ImGuiCond_FirstUseEver really pays off: your default layout is used only the first time, and after that the user's arrangement wins.

Performance tips

  • Skip hidden work: if Begin() returns false (collapsed or clipped), skip the panel's contents. The capstone panels already do this.
  • Long lists: use ImGuiListClipper so only visible rows are submitted. A hierarchy with 50,000 entities then costs the same as one with 50.
  • Avoid per-frame allocation in hot UI code: format into stack buffers, as the lessons do with _snprintf.
  • Profile it: ImGui itself is usually well under 1 ms. If it isn't, use the Metrics window to see vertex counts per window.
  • Idle throttling: an editor doesn't need 500 FPS when nothing moves. Keep VSync on, or sleep when there is no input.

In Metrics > Tools, the Item Picker lets you click any widget on screen and breaks into the debugger right where that widget is submitted. Very handy in a large editor codebase.

Game-engine angle

The most useful habit to take from this course is the immediate-mode mindset: the UI is a function of your data, re-run every frame. There is no widget tree to keep in sync and no "on changed" plumbing, so adding a debug panel takes minutes. Studios rely on that most of all. The polished editor is nice, but the throwaway tool window you can write in five minutes to debug an AI state machine or a physics glitch is where Dear ImGui really earns its place. Keep a Debug menu in your engine and fill it freely.
