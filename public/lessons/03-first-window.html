The two rules of every ImGui window

A window is opened with ImGui::Begin() and closed with ImGui::End(). Every widget you call in between is placed inside that window, top to bottom.

ImGui::Begin("Engine Controls");   // creates the window the first time, reuses it after that
    ImGui::Text("Hello, engine!");
ImGui::End();                      // must ALWAYS be called, even if Begin() returned false
  1. The title is the window's identity. Two Begin("Engine Controls") calls in the same frame add widgets to the same window.
  2. Always pair Begin with End. Begin() returns false when the window is collapsed or fully clipped. You may skip the widgets in that case, but you must still call End().
Where does this code run?

Your Lesson_UI() is called once every frame from the engine's Frame() function, between ImGui::NewFrame() and ImGui::Render(). That is the same spot as the widgets inside IMGUI_display() in the starter OGL.c.

Never pass user strings as the format.

ImGui::Text(entity.name) breaks if the name contains %. Use ImGui::TextUnformatted(entity.name) or ImGui::Text("%s", entity.name).

Buttons return what happened

This is the core idea of immediate mode. There are no callbacks or event listeners. A widget function draws the widget and returns what the user did with it this frame:

if (ImGui::Button("Reset scene"))     // true only on the frame of the click
{
    Engine_ResetScene();
    Engine_Log("Scene reset");
}

Checkboxes and radio buttons edit your variables directly

You pass a pointer to your own data. ImGui reads it to draw the widget, and writes to it when the user clicks. The engine variable is the UI state:

ImGui::Checkbox("Show grid", &gShowGrid);          // bool*

static int mode = 0;
ImGui::RadioButton("Slow", &mode, 0); ImGui::SameLine();
ImGui::RadioButton("Fast", &mode, 1);              // writes 1 into mode when clicked

They also return true on the frame the value changed, so you can react, for example to log a message or mark the scene "dirty" for saving.

Basic layout: SameLine, Separator, Spacing

  • ImGui::SameLine() puts the next widget to the right of the previous one.
  • ImGui::Separator() draws a horizontal line.
  • ImGui::Spacing() adds a little vertical space.

Window options

static bool showAbout = true;
// 2nd argument: pointer to bool adds a close [x] button that sets it to false
// 3rd argument: ImGuiWindowFlags
ImGui::Begin("About", &showAbout, ImGuiWindowFlags_AlwaysAutoResize | ImGuiWindowFlags_NoCollapse);

Common flags: NoTitleBar, NoResize, NoMove, NoCollapse, AlwaysAutoResize, NoBackground, MenuBar, NoSavedSettings.

Use SetNextWindowPos and SetNextWindowSize before Begin. With ImGuiCond_FirstUseEver they only apply the first time, so the user can still move and resize the window afterwards.

Game-engine angle

Most engine panels start exactly like this: a window that exposes global settings such as grid, wireframe, time scale and pause. Because Checkbox writes straight into gWireframe, you don't need a separate "UI model" to keep in sync. The engine data is the single source of truth.
