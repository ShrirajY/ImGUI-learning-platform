Picking one thing from many

An editor is full of "choose one" fields: mesh type, texture, material, shading mode, the entity you are editing. ImGui gives you two families of widgets for this:

  • Combos (drop-down boxes): compact, one line high, the list opens in a popup.
  • List boxes: an always-visible, scrollable list. Good for scene entities and asset browsers.

Both are built from the same building block: Selectable().

Combo with an array

The quickest form takes an int* index and an array of strings. The engine already has gMeshNames[MESH_COUNT], and Entity::mesh is an index into it, so it is a one-liner:

Entity *e = &gEntities[gSelectedEntity];
ImGui::Combo("Mesh", &e->mesh, gMeshNames, MESH_COUNT);   // returns true when changed

For short fixed lists there is also a zero-separated string version (the list must end with two zero bytes: your final \0 plus the one the compiler adds to every string literal):

static int preset = 2;
if (ImGui::Combo("Time scale", &preset, "Paused\0Half\0Normal\0Double\0Quad\0"))
    gTimeScale = speeds[preset];

Combos for enums

Keep a names array next to your enum, sized by a _COUNT entry. Then the combo index is the enum value:

enum ShadingMode { SHADE_LIT, SHADE_UNLIT, SHADE_WIREFRAME, SHADE_COUNT };
static const char *shadingNames[SHADE_COUNT] = { "Lit", "Unlit", "Wireframe" };
static int shading = SHADE_LIT;   // int, because Combo wants int*

if (ImGui::Combo("Shading", &shading, shadingNames, SHADE_COUNT))
    ApplyShading(shading);         // react only on change
Enum storage

Combo needs an int*. If your struct stores a C++ enum class or a uint8_t, copy it into a temporary int, call Combo, and write it back when it returns true.

Custom combos: BeginCombo / Selectable / EndCombo

When the list isn't a plain string array, or you want thumbnails, a "None" entry, separators or filtering inside the popup, build the combo yourself. BeginCombo draws the closed box with whatever preview text you pass, and returns true while the popup is open:

const char *preview = (e->texture >= 0) ? gTextures[e->texture].name : "None";
if (ImGui::BeginCombo("Texture", preview))
{
    if (ImGui::Selectable("None", e->texture < 0))
        e->texture = -1;

    for (int t = 0; t < gTextureCount; t++)
    {
        bool isSelected = (e->texture == t);
        ImGui::PushID(t);
        ImGui::Image(Engine_TexID(t), ImVec2(16, 16)); ImGui::SameLine();
        if (ImGui::Selectable(gTextures[t].name, isSelected))
            e->texture = t;
        if (isSelected)
            ImGui::SetItemDefaultFocus();   // opens scrolled to + keyboard-focused on current item
        ImGui::PopID();
    }
    ImGui::EndCombo();                      // only if BeginCombo returned true
}

Selectable(label, selected) draws a highlighted row when selected is true and returns true when clicked. It is read-only about selection: you decide what "selected" means and you update your own state. Inside a combo, clicking a Selectable also closes the popup automatically.

List boxes

// Quick version: array of strings, like Combo
static int item = 0;
ImGui::ListBox("Meshes", &item, gMeshNames, MESH_COUNT, 4);   // 4 rows tall

// Full version: any content you like
if (ImGui::BeginListBox("##entities", ImVec2(-FLT_MIN, 200)))
{
    for (int i = 0; i < gEntityCount; i++)
    {
        ImGui::PushID(i);
        if (ImGui::Selectable(gEntities[i].name, gSelectedEntity == i))
            gSelectedEntity = i;
        ImGui::PopID();
    }
    ImGui::EndListBox();
}

BeginListBox is a framed child window, so the same sizing rules apply: -FLT_MIN width fills the row, and a negative height leaves space below (for example -ImGui::GetFrameHeightWithSpacing() to keep one row of buttons visible).

Duplicate names = shared ID

Duplicate an entity and you get two rows called "Cube". With the same label they have the same ID, so clicking one can highlight both or not respond at all. Always PushID(i) / PopID() around rows in a loop, or append "##" plus the index to the label.

Double-click

Pass ImGuiSelectableFlags_AllowDoubleClick, then check ImGui::IsMouseDoubleClicked(ImGuiMouseButton_Left) when the Selectable returns true. In the lesson code, a double-click focuses the camera on the entity.

Search boxes: ImGuiTextFilter

ImGuiTextFilter is a small helper that owns an input buffer and parses it into include/exclude terms. Keep it static (it must survive between frames):

static ImGuiTextFilter filter;
filter.Draw("Filter", 200.0f);               // draws an InputText; returns true when edited

for (int i = 0; i < gEntityCount; i++)
    if (filter.PassFilter(gEntities[i].name))
        ImGui::Selectable(gEntities[i].name);
Filter textMatches
crNames containing "cr" (case-insensitive): Crate
cr,plContaining "cr" OR "pl": Crate, Planet
-groundEverything except names containing "ground"

Huge lists: ImGuiListClipper

A real project has thousands of assets. Submitting 10,000 Selectables every frame works, but it wastes CPU on rows nobody can see. ImGuiListClipper tells you which rows are visible in the current scroll position, so you only submit those:

ImGuiListClipper clipper;
clipper.Begin(itemCount);                    // optional 2nd arg: row height if known
while (clipper.Step())
    for (int row = clipper.DisplayStart; row < clipper.DisplayEnd; row++)
        ImGui::Selectable(names[row], row == selected);

The clipper needs every row to have the same height, and needs a random-access index. That is why you can't call PassFilter inside the clipper loop. When the filter changes, rebuild an array of matching indices, then clip that array:

if (filter.Draw("Search"))                   // only when the text changed
{
    filteredCount = 0;
    for (int i = 0; i < ASSET_COUNT; i++)
        if (filter.PassFilter(assetNames[i])) filtered[filteredCount++] = i;
}
clipper.Begin(filteredCount);                // ...then draw assetNames[filtered[row]]
Game-engine angle

Notice how little "editor state" we need. The texture combo writes directly into Entity::texture, and the entity list reads and writes gSelectedEntity. When you click an object in the 3D view, the engine changes gSelectedEntity and the list highlight follows on the next frame without any sync code. The only state we own is the filter text and the cached index list for the asset browser, which is pure UI state.
